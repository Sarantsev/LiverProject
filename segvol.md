# SegVol: модель и её применение в нашем проекте

Документ описывает базовую модель **SegVol** (что это и как устроено) и то, **как мы её
применяем** в СППВР для диагностики опухолей печени по КТ.

- Статья: *SegVol: Universal and Interactive Volumetric Medical Image Segmentation*,
  arXiv:2311.13385 (NeurIPS 2024 Spotlight).
- Веса/код: `BAAI/SegVol` (HuggingFace, `trust_remote_code`), репозиторий BAAI-DCAI/SegVol.

---

## Часть 1. Что такое SegVol

### Задача
SegVol — 3D **foundation-модель** для универсальной и интерактивной сегментации
объёмных медицинских изображений (КТ). Одна модель сегментирует **200+ анатомических
категорий** по **промптам**, а не обучается отдельно под каждую структуру.

### Масштаб обучения
- **~90 000 неразмеченных** КТ-объёмов (self-supervised предобучение энкодера).
- **~6 000 размеченных** КТ-объёмов (supervised + псевдо-метки на неразмеченных).
- **200+** анатомических категорий.
- Результат в статье: превосходит конкурентов в 19 из 22 бенчмарков, местами до +37.24%
  Dice относительно ближайшего метода.

### Архитектура (SAM-подобная, перенесённая в 3D)
SegVol повторяет структуру SAM (Segment Anything), но в объёме и с добавленным
текстовым промптом:

| Компонент | Что делает | Детали |
|---|---|---|
| **Image encoder** | кодирует объём в эмбеддинги | 3D **ViT** (MONAI), предобучен self-supervised на 90K КТ |
| **Prompt encoder** | кодирует промпты в sparse/dense эмбеддинги | SAM-style, 3D: point / box / text |
| **Mask decoder** | по эмбеддингам изображения + промптам выдаёт маску | transformer-декодер SAM-типа |
| **Text encoder** | кодирует текстовый промпт | **CLIP** (`CLIPTextModel`) → вектор 768 |

### Геометрия (фиксированная)
- Вход (ROI): **`[32, 256, 256]`** (D, H, W).
- Patch: **`[4, 16, 16]`** → сетка токенов **`[8, 16, 16]`**.
- Размерность эмбеддинга: **768**.
- Позиционные эмбеддинги ViT **жёстко привязаны к этой сетке** — поменять разрешение
  входа без переобучения энкодера нельзя.

### Промпты
Модель управляется как минимум одним промптом (можно комбинировать):
- **Point** — положительные/отрицательные точки-клики.
- **Bounding box** — 3D-рамка `[d0, h0, w0, d1, h1, w1]` в вокселях ROI. В коде рамку из
  маски строит `generate_box` (min/max nonzero по осям + опциональный джиттер `bbox_shift`).
- **Text** — текстовое имя структуры через CLIP.

Пространственные промпты (box/point) дают **сильную локализацию**; текст — слабее, это
семантический ориентир. (`prompt_encoder`: 4 point-embedding'а — pos/neg точка + 2 угла
рамки; box кодируется как два угловых «точечных» эмбеддинга.)

### Инференс: zoom-out-zoom-in
Чтобы покрыть большой объём при фиксированном ROI, SegVol сначала грубо сегментирует
уменьшенный объём (**zoom-out**), находит ROI вокруг цели, затем детально досегментирует
её скользящим окном в исходном разрешении (**zoom-in**). (`forward_test(..., use_zoom=True)`,
`logits2roi_coor`, sliding-window predictor.)

### Лоссы
Сегментация обучается комбинацией **Dice + BCE** (`BinaryDiceLoss` + `BCELoss` в коде).

## Часть 2. Как мы применяем SegVol в проекте

Цель проекта — СППВР по КТ печени: одновременно **сегментировать опухоль** и
**классифицировать её тип** (5 классов: HCC / ICC / CRLM / BCLM / HH). Мы не берём
SegVol «как есть», а строим вокруг него **мультизадачную обёртку**.

### Обёртка `SegVolMultiTask`
Файл: `liver_sppvr/models/segvol_multitask.py`. Берём из загруженного SegVol три родных
компонента — `image_encoder`, `prompt_encoder`, `mask_decoder` (+ `text_encoder`) — и
добавляем своё:

```
4 фазы КТ ──► [ViT-энкодер SegVol] ──► attention-fusion эмбеддингов
                                            │
                        ┌───────────────────┴───────────────────┐
                        ▼                                        ▼
        [prompt_encoder + mask_decoder]              [наша cls-голова]
          сегментация опухоли (Dice+BCE)         тип опухоли, 5 классов
                        │                                        ▲
                        └──────── маска (masked-pooling) ────────┘
```

### Отличия от «ванильного» SegVol

**1. Мультифазность (4 фазы КТ).**
Файл: `liver_sppvr/models/multiphase.py`. Вместо одного объёма подаём 4 фазы
(non_contrast / arterial / portal / delayed). В режиме `attention` каждая фаза
кодируется энкодером отдельно, затем эмбеддинги сливаются attention-fusion.

**2. Вторая голова — классификация типа.**
Файл: `liver_sppvr/models/cls_head.py`. Своя голова с **masked-pooling** по маске опухоли
(пулинг признаков только внутри маски) → 5 классов. Родные prompt/mask-декодеры SegVol
отвечают только за сегментацию.

**3. Мультизадачный лосс.**
Файл: `liver_sppvr/train/losses.py`. `loss = seg + cls`:
- seg — родной для SegVol **Dice + BCE**;
- cls — **Focal/взвешенная CE** (веса классов из-за дисбаланса редких BCLM/HH).

### Промпт сегментации: box из GT-маски
Ключевой прикладной выбор. Изначально мы промптили сегментацию **текстом**
`"liver tumor"` — но так dice упирался в потолок ~0.47 (SegVol слабо локализует из
текста). Перешли на **box-промпт** (`--seg-prompt box`): рамку строим из GT-маски
функцией `_masks_to_boxes` в `liver_sppvr/train/engine.py` — **точная реплика
`generate_box` из SegVol** (min/max nonzero по осям D,H,W, джиттер `bbox_shift` как
аугментация промпта на train, на eval без джиттера).

> **Важно про метрику.** Box-промпт использует рамку из GT-маски, поэтому `val_dice` в
> этом режиме отражает **semi-automatic** сценарий (врач даёт рамку → модель
> сегментирует). Это штатный режим SegVol и валидный для СППВР, но **не сравним «в лоб»**
> с полностью автоматической text-сегментацией. Переход на box сразу поднял val_dice
> выше 0.53 против текстовых ~0.47.

### Дообучение (fine-tuning) под наши данные
Файлы: `liver_sppvr/train/multitask.py`, `build.py`, `configs/default.yaml`.
Полный fine-tune энкодера переобучался (данных мало, ~400 пациентов). Внедрён
анти-оверфит-набор (флаги конфига + CLI-оверрайды):

- **LoRA на энкодере** (`--lora`, `liver_sppvr/models/lora.py`): база ViT заморожена,
  обучаются низкоранговые A/B в attention-слоях (`targets: [qkv]`, ~0.3M параметров) —
  энкодер дозированно адаптируется под КТ-домен без переобучения. Альтернатива —
  полная заморозка (`freeze_encoder: true`).
- **Аугментации** (`train.augment`, `liver_sppvr/data/augment.py`): флипы + intensity
  jitter, синхронно по фазам и маске.
- **Регуляризация:** `weight_decay: 1e-2`, `num_epochs: 80`, `early_stop_patience: 20`.
- **AMP** (`--amp`) + **DataParallel** на 2×L40 (`CUDA_VISIBLE_DEVICES=0,1`); autocast
  вынесен внутрь `forward`, чтобы работать в потоках-репликах DataParallel.

### Что мы НЕ используем из SegVol
- **Zoom-out-zoom-in инференс** — у нас фиксированный ROI `[32,256,256]` на весь
  прересэмпленный объём печени, без скользящего окна.
- **Мультиорганность (200+ категорий)** — нам нужна одна цель (опухоль), тип определяет
  отдельная cls-голова.

### Геометрия у нас = геометрия SegVol
`configs/default.yaml` повторяет фиксированные параметры SegVol: `spatial_size:
[32,256,256]`, `patch_size: [4,16,16]`, `embed_dim: 768`. Менять нельзя — сломаются
позиционные эмбеддинги предобученного энкодера. Отсюда следствие: мелкие опухоли на
глубине 32 частично теряются при ресэмпле — структурное ограничение, «зашитое» в SegVol.

## Запуск (актуальная команда)

```
CUDA_VISIBLE_DEVICES=0,1 TOKENIZERS_PARALLELISM=false PYTHONPATH=. \
python -m liver_sppvr.train.multitask --config configs/default.yaml \
  --work-dir ./work_dir_lora_box --num-workers 8 --batch-size 4 --amp --lora --seg-prompt box
```

Окружение: `segvol_env` (torch 1.13.1, python 3.10). Перед запуском — `nvidia-smi`,
карты должны быть свободны.
